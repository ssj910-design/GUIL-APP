# 안드로이드 APK 전환 계획 (Capacitor + FCM) — 2026-07-29

> 목적: 갤럭시 등 안드로이드에서 **잠금화면 푸시가 안 오는 문제**의 정공법.
> 웹앱(PWA) 자체는 유지하고, 안드로이드만 네이티브 껍데기(Capacitor)로 감싸 **네이티브 푸시(FCM)**로 배달한다.
> iOS는 이미 PWA 설치 시 푸시가 잘 와서 **PWA 유지**(iOS 네이티브는 애플 $99/년+Mac+심사라 별도).

## 0. 먼저 — APK 전에 공짜로 시도 (이걸로 되면 미룸)
안드로이드 미도달은 대부분 "웹이라서"가 아니라 **삼성 절전 + 미설치** 조합.
1. **크롬으로 "앱 설치"**(홈에 추가) → WebAPK 생성, 진짜 앱처럼 푸시
2. **설정 → 배터리 → 해당 앱 "제한 없음"**(절전 예외) ← 핵심일 확률 높음
3. 알림 권한 + **잠금화면 알림 켜짐** 확인
→ 되면 웹으로 충분. 안 되면 아래 진행. (네이티브여도 삼성 절전 예외 안내는 여전히 권장 — dontkillmyapp)

## 1. 방식
- 웹앱은 **Vercel에 그대로**. APK는 **라이브 URL을 띄우는 얇은 네이티브 WebView** + 네이티브 푸시 플러그인.
- **왜 FCM 필수**: Capacitor WebView는 웹푸시가 불안정 → 안드로이드는 **FCM 네이티브 푸시**로 다시 배달.
- **우리가 만든 알림 트리거·카탈로그(lib/notifications.js, 각 핸들러 notify)는 그대로 재사용.** 바뀌는 건 "마지막 배달" 계층 + 토큰 저장뿐.

## 2. 기간 (내부 사이드로드 기준, ~1주)
| 단계 | 내용 | 기간 |
|---|---|---|
| A | Capacitor Android 껍데기(WebView→라이브 URL), APK 빌드·서명·설치 | 1일 |
| B | Firebase/FCM 세팅(google-services.json) + @capacitor/push-notifications: 권한·토큰·알림 탭 이동 | 1~2일 |
| C | 서버: 네이티브 토큰 저장 + /api/push/send에 FCM 발송 분기(웹구독=web-push, 앱=FCM) | 1~2일 |
| D | 실제 갤럭시 실기기 테스트(잠금·백그라운드·절전), 잔버그 | 1일 |
| — | **합계** | **4~6일** |
- **배포 방식 확정: 사이드로드(웹사이트에서 직접 APK 다운로드)** — 플레이스토어 안 씀. 심사·$25·개인정보 양식 불필요(2~4일 절약). 상세는 3-1.

## 3. 계획 (단계)
1. Firebase 프로젝트 + Android 앱 등록 → `google-services.json`
2. Capacitor 추가(`@capacitor/core`,`cli`), `cap init`, Android 플랫폼 추가. `capacitor.config`의 `server.url`=라이브 URL
3. `@capacitor/push-notifications` 설치 + 안드로이드 알림 권한/채널
4. 클라: Capacitor 환경 감지 → FCM 토큰 등록 → `/api/push/register-native`로 저장(profileId+token)
5. 서버: `/api/push/send`에 FCM 분기 추가(Firebase Admin SDK/서버키로 토큰에 발송) — web-push와 병행
6. APK 빌드·서명(keystore) → 사이드로드(카톡 등으로 apk 배포) → 실기기 테스트
7. (선택) 앱명·아이콘·스플래시, 알림 탭 시 해당 화면 딥링크

## 3-1. 배포 방식 — 사이드로드(직접 다운로드) 확정 (안드로이드 전용)
- 우리 사이트에 APK 올려두고 **다운로드 페이지 + 설치 안내**로 배포. (iOS는 사이드로드 불가 → PWA 유지)
- **장점**: 무료·심사 없음·즉시 배포·완전한 통제.
- **주의(현장 안내 필요)**:
  1. 설치 시 **"출처를 알 수 없는 앱 허용"** 켜야 함(안드로이드 경고) → 스샷 안내 첨부
  2. **Play Protect 경고**("검사되지 않은 앱")가 뜰 수 있음 → "무시하고 설치" 안내
  3. **자동 업데이트 없음** — 새 APK 나오면 수동 재설치. 단 **라이브 URL 방식이라 웹 변경은 재설치 불필요**, 껍데기 바뀔 때만
- **업데이트 매끄럽게(선택)**: 앱에서 "설치 버전 vs 서버 최신 버전" 비교 → 새 버전이면 "여기서 받으세요" 배너. 작은 기능
- 호스팅: Vercel 정적 파일 또는 Supabase 스토리지에 apk 두고 링크

## 4. 수정/전환 시 이슈
1. **푸시 이중 배달**: 앱 유저=FCM, 브라우저 유저=web-push 병행. 한 사람이 둘 다면 중복 알림 가능 → 기기 관리/우선순위 정리
2. **트리거·카탈로그 재사용**(다행) — 배달 계층 + 토큰 저장만 추가
3. **새 의존성**: Firebase(google-services.json, Admin SDK 서버키) — 환경변수 추가
4. **iOS는 PWA 유지** — 안드로이드 APK만. iOS 네이티브 원하면 애플 $99/년+Mac+심사 별도
5. **배포/업데이트**: 라이브 URL이라 **웹 수정은 즉시 반영(재설치 불필요)**. APK 껍데기·아이콘·플러그인 바뀔 때만 재배포. 사이드로드=수동, 스토어=심사
6. **삼성 절전**: 네이티브여도 배터리 최적화 예외 안내 필요할 수 있음(앱 첫 실행 안내)
7. **화이트라벨**: APK 패키지명·앱명·아이콘 고정 → 타사 입주 시 **테넌트별 앱을 새로 빌드·서명·배포**해야(웹보다 무거움). 멀티테넌트 계획과 얽힘
8. **서명 키(keystore) 관리**: 분실하면 같은 앱 업데이트 배포 불가 — 안전 보관 필수
9. **WebView 원격 로딩 제약**: 오프라인·일부 네이티브 기능 제한. 우리 앱은 온라인 전제라 대체로 무방
10. **빌드 환경 유지보수**: 안드로이드 스튜디오/빌드 체인 관리 추가

## 5. 서버 플랜과 독립
- Capacitor 전환은 **Vercel Hobby/Pro와 무관**. 크론(pg_cron)·웹앱은 그대로.

## 6. 추천
1. **공짜 3개 먼저**(크롬 설치+절전 예외+잠금알림) — 되면 APK 미룸
2. 안 되거나 "제대로 앱으로" → **안드로이드 APK(Capacitor+FCM) ~1주**, iOS는 PWA 유지
3. 트리거는 이미 있으니 **배달 계층만 추가** — 생각보다 크지 않음
