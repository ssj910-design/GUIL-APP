PRD — 제품 정의서 v0.2

2026-07-30 · 작성 차호근+클로드 · 독자: 차호근·ssj910 (내부 기준서) · ← 설계 허브로

1. 한 줄 정의 확정

승강기(엘리베이터·에스컬레이터) 유지보수 회사를 위한 스마트 현장관리(FSM) 서비스
— 고장·점검·자재·근태·소통을 앱 하나로, 종이 없이.

※ 장르: FSM(현장 서비스 관리) — 기사를 현장에 보내고 작업을 접수부터 완료까지 관리하는 소프트웨어 장르. CRM(고객관리)·SI(외주개발)가 아니다. 판매 방식은 SaaS(설치 없는 구독형).
※ 법령상 "승강기"는 엘리베이터(승객·화물·자동차용 카리프트 포함)+에스컬레이터+휠체어리프트를 포함. 기계식 주차설비(타워·퍼즐식)는 별도 법령(주차장법)이지만 같은 업체가 겸업하는 현장이 많아 지원 대상에 포함한다.

2. 우리가 푸는 문제

유지보수 업체의 현장 업무는 대부분 수동·아날로그로 흩어져 있다:

지금까지의 방식무엇이 아픈가
전화·카톡방·네이버밴드로 고장 접수고장을 한곳에서 계속 볼 수 없다 — 누가 잡았는지, 처리됐는지 흐른다
점검일지 수기 기록, 밴드에 사진 올리기기록이 흩어지고 같은 내용을 여러 서류에 중복 작성
자재·견적을 구두/엑셀로 관리누락·재고 꼬임 — 신청했는지, 줬는지, 청구했는지 추적 불가
출근·당직·연차를 수기/엑셀로관리자가 현황을 실시간으로 모른다
고장 처리 노하우가 베테랑 머릿속에만경험이 회사 자산으로 안 남는다 — 사람이 나가면 같이 사라지고, 신입은 같은 고장을 처음부터 다시 헤맨다

해결: 이 모든 흐름을 앱 하나에 모으고, 각 단계가 다음 단계를 자동으로 만든다 (고장접수→배정→출동→처리, 자재 지급완료→할일 자동 생성→비용청구, 자체점검→공단 제출).

3. 사용자

역할주 화면하는 일
기사(현장요원)모바일 앱(PWA)출근체크, 고장 출동·처리, 점검, 자재신청, 우리방
중간관리자모바일 관리자모드 + PC 콘솔고장 배정, 자재·견적 처리, 근태 확인
최고관리자PC 콘솔(전체 권한)+ 관리자 계정·비용청구 확정·회사 설정·당직표
건물주(고객)미정먼 미래 — 내 건물 승강기 상태·점검 이력 열람 포털
제품 형태 (중요): 관리자용이 둘이다 — ① 모바일 관리자모드(기사 앱 안, 이동 중 즉시 처리: 배정·자재승인) ② PC 관리자 콘솔(/admin, 심화 관리: 통계·설정·등록). 기사와 관리자 모두 설치 없는 웹앱(PWA)이 기본, 안드로이드는 APK 배포 예정(APK-PLAN).

4. 기능 지도 (덩어리)

고장

접수(앱/콘솔) → 배정/선착순 → 출동 응답 → 도착 → 처리결과. 미배정·미응답 자동 재촉 알림

점검·검사

자체점검(공단 제출 체계), 정기점검 일정, 검사관리(국가승강기정보센터 실시간 연동)

자재·견적·비용청구

기사 신청 → 관리자 지급 → 할일 자동 생성 → 교체 확인 → 비용청구. 상비부품 재고

근태

출근체크(위치 선택), 당직·숙직표, 연차 신청·승인, 근무 교환

소통

우리방(게시판·공지·멘션), 푸시 알림 20여 종(즉시형+예약형), 건의하기

관제·위치

기사 실시간 위치 지도(관제), 거리 기반 배정 추천, 티맵 경로·도착 ETA, 티맵·카카오 길안내, 고객 도착예정 문자

지식 아카이브 초석만

고장 처리 이력이 검색 가능한 회사 자산으로 쌓임 — AI 검색(RAG) 기반은 깔려 있음(pgvector), 활용은 예정

현장 데이터

현장·호기(승강기 단위) 관리, 담당자, 계약, 엑셀 업로드

5. 사업 방향 (단계)

  1. 1단계 (지금): 구일엘리베이터에서 완성 — 실사용으로 검증
  2. 2단계: 화이트라벨로 타사 입주 (구일 흔적 제거, 회사별 분리 — MULTITENANT-PLAN)
  3. 3단계: 부분 유료화 — 일부 기능 무료 + 일부 유료 경계 미정, 광고(자재유통·보험·렌트 등 현장 관련 업체)
  4. 확장 기능: 회계·급여 등 사무 전산, 미수금(못 받은 돈) 체킹 — 현장관리가 자리 잡은 뒤
  5. 장기: 승강기를 넘어 "현장관리"가 필요한 업종 전반으로 확장. 인수(M&A) 가능성도 열어둠

6. 대상 시장

한국 승강기 유지보수 업계 — 소규모 업체가 대다수인 시장. 우선 소규모(기사 1~10명)를 완벽 지원하고, 중견까지 확장.

7. 성공 기준

단계기준
1차 (오픈 후)종이가 없어진다 — 수기 점검일지·다중 서류 제로, 기사 전원이 매일 앱으로 출근·고장·점검 처리
2차카톡방·밴드로 하던 업무 소통이 앱(우리방·알림)으로 대체
3차첫 타사 입주 시점 미정

8. 지금 하지 않는 것 (Non-goals)

  • 건물주(고객) 포털 — 먼 미래
  • iOS 네이티브 앱 — PWA로 충분 (안드로이드만 APK)
  • 완전 오프라인 지원 — 구조상 불가(온라인 전제)

※ 회계·급여·미수금은 "안 한다"가 아니라 나중에 한다 — 5장 확장 기능으로 이동.

이전 버전 (v0.1) 목록에 "회계·급여 등 사무 전산 — 현장 업무에 집중"이 non-goal로 있었음 → v0.2에서 확장 기능(5장)으로 이동, 미수금 체킹 추가.

9. 변경 이력

방향이 바뀌는 수정만 버전을 올리고 여기 남긴다 (오타·문구 다듬기는 제외). 전체 기록은 git 이력.

10. 용어집

용어뜻
승강기법령상 엘리베이터(승객·화물·자동차용 카리프트)+에스컬레이터+휠체어리프트 총칭. 기계식 주차설비는 별도 법령이나 지원 대상
RAG회사 데이터(고장 이력 등)를 AI가 검색해 답하게 하는 기술 — 초석(pgvector)은 깔려 있음
호기한 현장 안의 승강기 한 대 (예: 24호기)
자체점검업체가 매월 수행해 공단에 제출하는 법정 점검
