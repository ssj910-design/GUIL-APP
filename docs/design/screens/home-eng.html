2. 화면 요소

요소설명
헤더회사명(화이트라벨 대상) + 마이페이지 + 알림종(안읽음 배지)
출근 체크하루 1회, GPS 1회 수집(거부해도 체크는 됨 — 좌표만 빈다). 퇴근·당직 마감도 이 버튼이 상태 따라 변신
워크 캘린더 미리보기이번 주 근무 스트립 — 전체보기로 워크캘린더 탭 이동
고장 처리 현황본인 배정 + 미배정(선착순용)만, 완료 제외, 거리순 정렬(가까운 현장 먼저)
집중관리현장갇힘 1건 이상 or 최근 30일 호기 단위 3회 이상 고장 — 전 기사 공통 노출(의도)
실시간 검사 관제국가승강기정보센터 API — 검사도래·조건부/불합격. 공공데이터 배지 + LIVE
게시판 플로팅안읽음 수(빨강)·멘션(노랑) 배지. 게시판 탭을 여는 순간 전체 읽음 처리

3. 필요 요소 (동작 전제)

  • attendances — 출근체크 upsert(profile_id+work_date 유니크)
  • failures — 고장 현황·집중관리 판정의 원천
  • 기사 GPS 권한 — 거리순 정렬·출동 배정 기준. 거부 시에도 화면은 동작(정렬만 기본순)
  • 국가승강기정보센터 API 키(플랫폼 공용) — 실시간 검사 관제

4. QA 체크포인트 — 2026-08-04 전 항목 검증 완료

  1. ✅ 출근체크 중복 방지 — upsert 하루 1행. 퇴근이 출근보다 먼저 못 찍힘, 재출근 시 이전 퇴근기록 초기화
  2. ✅ 고장 현황 필터 — 남의 배정건 안 보임. 미배정 노출은 선착순 잡기용 의도
  3. ✅ 게시판 배지 — 전체 글 수 아님, profiles.feed_read_at 기준 진짜 안읽음
  4. ✅ 공공 API 실패 시 — 화면 안 깨지고 error 상태로 버팀
  5. ✅ 집중관리 전 기사 공통 노출 — 의도 확인(2026-08-04)

5. 알려진 한계 (보류 중)

  • 신고자 안내문자(SMS) 미구현 — 출동응답의 허위 "발송 완료" 안내는 2026-08-04 제거. 실제 발송은 SMS 업체 계약 필요
  • 기기 미등록자는 알림 없음 — 온보딩 체크리스트 5장에 반영(구일 4/20명 교훈)
