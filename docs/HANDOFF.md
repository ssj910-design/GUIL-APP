## 🔴 대기 중 — DB 자동 백업 켜기 (차호근 → 친구, 2026-08-04, 5분 작업)

> **실운영 DB에 지금 자동 백업이 없다.** 스크립트·스케줄러는 차호근 쪽 맥에 전부 세팅돼 있고
> (매일 21:00 pg_dump → 로컬 14일 + iCloud 30일 이중 보관), **Supabase 접속 문자열 한 줄만 필요해.**

1. Supabase 대시보드 → 구일 프로젝트 → **Connect** → **Session pooler** URI 복사
   (`postgresql://postgres.xxxx:[비밀번호]@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres`)
2. `[YOUR-PASSWORD]`를 실제 DB 비밀번호로 바꿔서 (모르면 같은 화면 Reset database password —
   anon key와 무관해서 앱엔 영향 없음. 단 어딘가 DB 비번을 직접 쓰는 게 있으면 그것만 갱신)
3. 차호근에게 전달 (직접 만나서/전화로 — 카톡 평문 지양) → 차호근이 `eleva/backups/.dbenv`에 넣고 시험 실행

이게 되면: 사고 시 하루 전으로 복구 가능 + 나중에 구일→Eleva 이사 리허설 재료도 됨.

**🏁 근무 종료**
3. 근무 종료 시, 오늘 근무표에 당직/숙직이면 그 버튼이 자동으로 뜸 (기사가 직접 안 고름). 맞아?
4. 근무표에 배정돼 있어도 [퇴근] 버튼은 남겨둠. 맞아?
5. 숙직 기사는 마감 버튼을 언제 눌러? (저녁 퇴근 전 / 다음날 새벽·아침) — 자정 넘김 처리 방향이 여기서 갈림. `docs/ATTENDANCE.md` 알려진 이슈 1번 참고.

**📍 위치**
6. 위치는 출근·현장도착·처리완료·근무종료 + 대기 중 2시간마다 자동. 이 정도면 적절해?
7. 위치 공유를 꺼도 출근은 됨 (가까운 현장 우선 배정에서만 빠짐). 맞아?
8. 위치 권한을 안 켜면 출근 버튼이 비활성. 맞아?

**👀 관리자**
9. 위치 안 켠 기사 안내는 게시판 말고 본인 앱 모달로만. 맞아?
10. 근무 중 2시간+ 앱 미확인은 관리자에게만 경고 (기사 화면엔 안 보임). 맞아?

## 🚀 배포 운영 방침 (2026-07-21 합의)

> **앞으로 차호근 쪽(+클로드)은 커밋·push만 하고, 운영 배포는 친구가 판단해서 반영합니다.**
> `vercel.json`의 `ignoreCommand` 때문에 일반 push는 배포가 스킵됨(한도 절약). 운영 반영은
> 커밋 메시지에 `[deploy]`를 넣거나 `npm run deploy`(빈 `[deploy]` 커밋)로만 트리거됩니다.
> 차호근 쪽에서는 이제 `[deploy]`를 붙이지 않으니, **반영 타이밍은 친구가 정하면 됩니다.**
>
> **⚠️ 클로드 주의 (2026-07-22 재확인):** `[deploy]`는 사용자가 **"배포해줘" 등으로 명시적으로
> 요청했을 때만** 붙인다. "그대론데?" 같은 확인·불만 표현은 배포 요청이 아니다 — 반영이 안 됐다는
> 뜻일 수도 있지만, 그 판단(지금 배포할지 나중에 모아서 할지)은 항상 사용자 몫이니 먼저 물어볼 것.

**✅ 2026-07-21 작업분 — 2026-07-22 `[deploy]` 커밋으로 배포 완료** (출근 UX 전반, 위치 안내 문구·본인 앱 모달 전환,
백엔드 버그 3건 수정, `docs/ATTENDANCE.md` 등). 이후 새로 커밋된 변경은 다시 배포 대기 상태입니다.

- **푸시알림건 — 눌러도 해당 화면으로 안 감 (안드로이드 관리자에게 전체 이관, 2026-08-01)**

  > 아래 두 파트(①네이티브 딥링크 미동작, ②팝업→실제화면이동 전환) 전부 안드로이드

  ### ① 네이티브 앱에서 딥링크 자체가 안 먹음

  **증상**: 설치된 안드로이드 앱에서 푸시알림(예: 게시판 @멘션)을 누르면, 앱이 켜져 있든
  꺼져 있든 그 알림에 해당하는 화면으로 안 가고 **그냥 마지막으로 보고 있던 탭 그대로** 뜬다.
  포그라운드 중 받은 알림을 앱이 직접 띄우는 상단 배너(아래 참고)를 탭해도 마찬가지로 이동
  안 하고 배너만 사라짐.

  **웹(PWA) 쪽은 확인·수정·배포 완료** — `푸시알림 딥링크가 실제로 안 먹던 근본 원인 두 가지
  수정` 커밋(app/components/ElevatorFieldApp.jsx, public/sw.js)에서 딥링크 처리 로직 버그
  2개(관리자 계정에서만 동작, 앱이 이미 떠 있을 때 재확인 안 함)를 고쳤고 웹 경로는 정상
  동작 확인함.

  **네이티브만 안 됨** — 앱이 이미 켜진 상태(포그라운드)에서도 안 되는 걸 보면,
  `pushNotificationActionPerformed`/`pushNotificationReceived`(`lib/push.js`) 이벤트 자체가
  안 불리거나, 불려도 `notification.data.url`이 비어있을 가능성이 큼. 탭(action performed)과
  수신(received) 둘 다 같은 증상이라 "탭 처리 로직"보다는 **FCM data payload가 안드로이드
  쪽에서 JS로 아예 안 넘어오는 문제**일 가능성이 높음.

  **확인 필요한 것**: 실제 기기에서 `adb logcat`으로 두 이벤트가 호출되는지, 호출된다면
  `notification.data`에 `url`이 제대로 들어있는지. `app/api/push/send/route.js`의 FCM
  발송 부분(`data: { url, tag }`)과 실제 기기 도착값을 비교. 관련 파일:
  - `android/app/src/main/AndroidManifest.xml` — `MainActivity`는 `launchMode="singleTask"`로
    이미 설정돼 있어 백그라운드 상태에서도 `onNewIntent`가 불려야 정상.
  - `android/app/src/main/java/com/guilelevator/app/MainActivity.java` — `onNewIntent`를
    따로 오버라이드하지 않고 `BridgeActivity` 기본 동작에 의존 중.
  - `lib/push.js`의 `onPushNotificationOpened`/`onPushNotificationReceived` — FCM data를
    받아 처리하는 JS 쪽 코드(정상으로 보임, 아마 여기까지 데이터가 안 옴).

  원인 찾으면 네이티브 코드 수정 + APK 재빌드·재배포 필요(웹 배포만으론 안 됨). 임시
  완화책으로 포그라운드 중 받은 푸시를 상단 배너로 직접 보여주는 기능은 이미 배포함(못 보고
  넘어가는 문제만 줄임, 딥링크 자체는 여전히 안 됨).

  ### ② 알림 27종 중 25종이 팝업만 뜨고 실제 화면이동은 안 됨 (네이티브 문제와 별개)

  코드 전수조사 결과, 눌렀을 때 **그 탭으로 실제 이동해서 상세를 보여주는 건 자재신청
  (`material_requested`)·견적신청(`quote_requested`) 2종뿐**. 나머지 25종은:
  - **탭 이동 없이 지금 화면 위에 팝업(Sheet)만 뜸** (12종): 고장 8종(배정·미배정·접수·
    거부·중대·재배정·미배정15분·미응답5분), 할일재배정요청, 자재·견적 취소됨 2종,
    게시판공지(관리자 상단고정 경로)
  - **딥링크 자체가 없어 앱 첫 화면(`/`)만 열림** (13종): 근무교환 요청·결과, 내일 당직·
    숙직, 출근체크안함, 출근미체크요약, 자체점검미완료, 오늘정기검사, 계약만료D-30,
    내연차승인·반려, 연차신청, 자체점검 공단제출실패, 자재/견적/상비부품 지급완료
    수령확인, PC관리자콘솔(RoomAdmin.jsx)에서 올린 게시판 @멘션·공지

  **왜 이렇게 돼 있는지**: 자재/견적만 되는 이유는 관리자모드 안의 자재/견적 패널이
  `focusId`라는 prop을 받아서 "이 아코디언 열고 이 건 상세 보여줘"를 그 탭 내부 상태로
  처리하기 때문(`app/components/tabs/AdminTab.jsx`의 `MaterialsPanel`/`QuotesPanel` 참고 —
  `focusId`/`onFocusHandled`, effect 없이 렌더 시점에 반영하는 패턴). 나머지는 앱
  최상위(`ElevatorFieldApp.jsx`)에서 탭이랑 무관하게 시트만 띄우는 방식이라, 각 탭
  컴포넌트에 자재/견적처럼 `focusId` prop을 추가해서 그 탭 고유의 상세보기 상태에
  연결해주는 작업이 필요함 (예: `FailureTab`은 이미 `detailTarget`이라는 자체 상세보기
  상태가 있음 — 거기 연결).

  **작업 규모**: 탭 컴포넌트 6~7개(고장·할일·게시판·워크캘린더·자체점검·검사관리·자재) +
  PC관리자콘솔(RoomAdmin.jsx)까지 손봐야 함. 고장 탭은 배정대기/출동/처리 등 하위 화면이
  여러 개라 어느 화면으로 갈지도 같이 정해야 해서 상대적으로 큼. 우선순위 제안:
  1. 탭 이동만으로 충분한 것부터 (근무교환은 화면에 자동으로 뜨는 팝업이 이미 있어서
     탭만 옮기면 됨, 출근·자체점검·검사·계약만료도 리스트형이라 탭 이동으로 충분)
  2. 이미 있는 탭 내부 상세보기에 focusId 연결 (고장·할일·게시판·자재취소)
  3. 상세 화면 자체가 없는 것(연차신청 관리자 승인화면, 자체점검 공단제출실패 상세,
     지급완료 수령확인 상세)은 새로 설계 필요 — 별도 논의 권장

  이 부분은 네이티브 이슈가 해결돼도 자동으로 같이 해결되는 게 아니라 **별도 프론트엔드
  작업**이니, 처리 순서(①번 먼저 or 동시에)는 안드로이드 관리자 판단에 맡깁니다.
