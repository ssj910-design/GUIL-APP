## 🚨 지금 장애 — 관리자 콘솔 로그인 불가 (2026-08-11 발견, 1분 수정)

> `/api/login`이 **500 "서버 설정 오류 — SUPABASE_JWT_SECRET 미설정"**을 반환한다.
> 커밋 b67828c(관리자 콘솔 JWT 로그인)가 요구하는 환경변수가 Vercel에 없어서다.
>
> **영향**: 관리자 콘솔(/admin) 신규 로그인 전면 불가. 이미 로그인된 브라우저는 세션이 남아 동작.
> 기사 앱(/)은 verify_login RPC 직접 호출이라 **영향 없음**.
>
> **수정**: Vercel → Settings → Environment Variables (Production)
> - 이름 `SUPABASE_JWT_SECRET`
> - 값: Supabase 대시보드 → Project Settings → API → **JWT Settings → JWT Secret**
> 등록 후 재배포.
>
> 확인법: `curl -X POST https://guil-app-pi.vercel.app/api/login -H 'Content-Type: application/json' -d '{"loginId":"x","password":"x"}'`
> → "아이디 또는 비밀번호가 올바르지 않습니다"가 나오면 정상(500이 아니면 됨).


## 🐛 발견 — 관리자 로그인 24시간 뒤 자동 만료, 재로그인 유도 없음 (2026-08-14 발견)

> 재고관리 기능 테스트 중 발견(사진 업로드 실패로 처음 드러남). `/api/login`이 발급하는
> JWT가 24시간 뒤 만료되는데(`app/api/login/route.js:54`, `expiresIn: "24h"`), 만료를
> 감지해서 재로그인시키거나 토큰을 갱신하는 로직이 어디에도 없다.
>
> **증상**: 관리자 콘솔 브라우저 탭을 24시간 넘게 열어둔 채로(또는 그 이상 지난 세션으로)
> 쓰다가 뭔가 저장을 시도하면(사진 업로드뿐 아니라 로그인이 필요한 모든 쓰기가 동일하게
> 걸림 — 제품 저장, 견적 작성 등) 아래 alert가 뜬다:
>
> `OO에 실패했습니다: "exp" claim timestamp check failed`
>
> 일반 직원은 원인을 알 수 없는 문구라 당황할 수 있다.
>
> **임시조치**: 로그아웃 후 재로그인하면 바로 해결(새 토큰 발급).
>
> **근본 수정 방향**: `AdminApp.jsx`의 로그인 세션 복원 로직(82~104번 줄)이나 Supabase
> 요청 공통 처리 지점에서 "exp" 관련 에러를 감지해 자동으로 로그인 화면으로 돌려보내거나
> 토큰을 갱신하도록 추가. 관리자 콘솔 전체에 걸친 영향이라 재고관리 작업 범위 밖 —
> 언제·누가 처리할지 별도 논의 필요.

## 🚀 배포 운영 방침 (2026-07-21 합의)

> **앞으로 차호근 쪽(+클로드)은 커밋·push만 하고, 운영 배포는 친구가 판단해서 반영합니다.**
> `vercel.json`의 `ignoreCommand` 때문에 일반 push는 배포가 스킵됨(한도 절약). 운영 반영은
> 커밋 메시지에 `[deploy]`를 넣거나 `npm run deploy`(빈 `[deploy]` 커밋)로만 트리거됩니다.
> 차호근 쪽에서는 이제 `[deploy]`를 붙이지 않으니, **반영 타이밍은 친구가 정하면 됩니다.**
>
> **⚠️ 클로드 주의 (2026-07-22 재확인):** `[deploy]`는 사용자가 **"배포해줘" 등으로 명시적으로
> 요청했을 때만** 붙인다. "그대론데?" 같은 확인·불만 표현은 배포 요청이 아니다 — 반영이 안 됐다는
> 뜻일 수도 있지만, 그 판단(지금 배포할지 나중에 모아서 할지)은 항상 사용자 몫이니 먼저 물어볼 것.

## 🔴 대기 중

- **사진/파일 다운로드 시 "다운로드 완료" 알림이 여러 개 중복으로 뜸 (네이티브 코드 수정함, APK 재빌드·재배포 필요, 2026-08-14)**

  **증상**: 설치된 안드로이드 앱에서 사진 전체보기의 "이 사진만 저장"/"○장 모두 저장"이나
  워크캘린더 등의 파일 다운로드를 누르면, 실제 파일은 1개만 저장되는데 알림창엔 "다운로드가
  완료되었습니다" 알림이 여러 개(스크린샷 기준 7~9개+) 뜬다. 재고관리 사진, 현장정보 부품현황
  사진, 근무표 내보내기(`2026-08-13-multi-manager...`)까지 기능·화면 무관하게 동일하게 발생 —
  다운로드가 걸리는 공통 경로인 `android/app/src/main/java/com/guilelevator/app/MainActivity.java`의
  `WebView.setDownloadListener` 쪽 문제로 추정.

  **원인 추정**: 파일이 실제로 1개만 저장되는 걸 보면 `DownloadManager.enqueue()`가 여러 번
  호출되고 있을 가능성이 큼 — 웹뷰가 같은 다운로드 URL에 대해 리스너 콜백을 두 번 이상
  연달아 부르는 것으로 보임(정확한 원인은 더 안 팜, `adb logcat`으로 실제 호출 횟수 확인하면
  더 명확해질 것).

  **적용한 임시 조치**: `setDownloadListener` 콜백에 URL+시간 기반 디바운스를 추가함(같은 URL이
  2초 안에 다시 들어오면 무시). 근본 원인(왜 중복 호출되는지)은 안 고친 우회책이라 표시해둠
  — 알림 중복이 다시 보이면 `adb logcat`으로 실제 호출 횟수부터 확인 필요.

  **필요한 작업**: 이 네이티브 코드 수정은 웹 배포(Vercel)로는 반영 안 됨 — APK를 다시 빌드해서
  기기에 재설치해야 함. `gradlew assembleDebug`/`assembleRelease`는 이 환경에서 정상 동작 확인함
  (Android Studio 번들 JBR로 컴파일 성공). 다만 release 빌드는 서명이 안 돼 있음
  (`android/app/build.gradle`에 signingConfig가 없어 `assembleRelease`를 돌리면
  `app-release-unsigned.apk`가 나옴) — 기존 배포용 `android/app/release/app-release.apk`는
  Android Studio의 Generate Signed Bundle/APK 같은 별도 서명 과정을 거친 것으로 보임. 그
  서명 키스토어를 아는 쪽에서 Android Studio로 Signed APK를 새로 뽑아 기기에 재설치하면 됨.

- **푸시알림건 — 눌러도 해당 화면으로 안 감 (안드로이드 관리자에게 전체 이관, 2026-08-01)**

  **증상**: 설치된 안드로이드 앱에서 푸시알림(예: 게시판 @멘션)을 누르면, 앱이 켜져 있든

  **웹(PWA) 쪽은 확인·수정·배포 완료** — `푸시알림 딥링크가 실제로 안 먹던 근본 원인 두 가지

  안 불리거나, 불려도 `notification.data.url`이 비어있을 가능성이 큼. 탭(action performed)과
  수신(received) 둘 다 같은 증상이라 "탭 처리 로직"보다는 **FCM data payload가 안드로이드
  쪽에서 JS로 아예 안 넘어오는 문제**일 가능성이 높음.

  **확인 필요한 것**: 실제 기기에서 `adb logcat`으로 두 이벤트가 호출되는지, 호출된다면
  `notification.data`에 `url`이 제대로 들어있는지. `app/api/push/send/route.js`의 FCM
  발송 부분(`data: { url, tag }`)과 실제 기기 도착값을 비교. 관련 파일:
  - `android/app/src/main/AndroidManifest.xml` — `MainActivity`는 `launchMode="singleTask"`로
    이미 설정돼 있어 백그라운드 상태에서도 `onNewIntent`가 불려야 정상.
  - `android/app/src/main/java/com/guilelevator/app/MainActivity.java` — `onNewIntent`를
    따로 오버라이드하지 않고 `BridgeActivity` 기본 동작에 의존 중.
  - `lib/push.js`의 `onPushNotificationOpened`/`onPushNotificationReceived` — FCM data를
    받아 처리하는 JS 쪽 코드(정상으로 보임, 아마 여기까지 데이터가 안 옴).

  원인 찾으면 네이티브 코드 수정 + APK 재빌드·재배포 필요(웹 배포만으론 안 됨). 임시
  완화책으로 포그라운드 중 받은 푸시를 상단 배너로 직접 보여주는 기능은 이미 배포함(못 보고
  넘어가는 문제만 줄임, 딥링크 자체는 여전히 안 됨).
