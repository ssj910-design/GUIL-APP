# 검사관리 — 조건부/불합격 필터 분리 + "개정법 조건부" (보류 중)

상태: **보류** (2026-09-30 논의 종료, 코드 미반영). 마이그레이션 `supabase/migrations/146_units_revised_law_conditional_DRAFT.sql`은
파일만 있고 **실행하지 않았다**. 아래 설계대로 진행하려면 컬럼이 하나 더 필요하다(§4).

## 왜

- 지금은 검사관리 필터가 "조건부·불합격" 한 덩어리라 불합격만/조건부만 따로 못 본다.
- 개정법 때문에 유예(연장)를 받은 호기를 따로 모아 보고 싶다. 공단 판정값이 아니라 **관리자가 수동으로 분류**하는 값이다.

## 1. 탭(필터) 구성

| 탭 | 대상 |
|---|---|
| 전체 | 지금과 동일 |
| 조건부합격 | 판정이 조건부합격인 건. 단 아래 "개정법으로 옮긴 그 검사 건"은 제외 |
| 개정법 조건부 | 개정법 표시가 켜진 건 **전부** (차기안전검사·조건부합격·합격 무관) |
| 불합격 | 판정이 불합격인 건만 |

## 2. 조건부 탭에서 빼는 기준 (핵심)

- 개정법으로 옮길 때 **그 시점의 검사유효기간 시작일**을 같이 기록한다.
- 조건부 탭에서 빼는 건: 개정법 표시가 켜져 있고 **기록된 시작일 == 현재 검사유효기간 시작일**인 건(= 옮긴 그 검사 그대로).
- 1년 뒤 새 검사를 받아 시작일이 바뀌고 또 조건부가 나오면 → **조건부 탭에 다시 나온다**(개정법 탭에도 그대로 남음). 이때 조건부 탭 행에는 `개정법` 배지를 붙인다.
- 그 건을 다시 개정법으로 "옮기면" 기록 시작일이 새 검사 기준으로 갱신되며 같은 동작이 반복된다.

## 3. 개정법 표시 켜고 끄기

- **자동 해제 없음.** 판정이 합격으로 바뀌어도 탭에 남는다. 연장이 끝났다고 판단할 때 관리자가 직접 끈다.
  (자동 해제를 넣으면 1년 검사 직후 잠깐 합격으로 뜨는 구간에서 목록에서 사라졌다가 다시 넣어야 한다.)
- 켜고 끄는 UI: 조건부·개정법 탭 행의 **구분 드롭다운**(조건부합격 ↔ 개정법 조건부). 부품교체내역 청구방식과 같은 방식.
- 대상: 조건부합격·차기안전검사·합격. **불합격은 제외.**

## 4. DB

```sql
alter table public.units add column if not exists revised_law_conditional boolean not null default false;
alter table public.units add column if not exists revised_law_marked_start date; -- 개정법으로 옮긴 시점의 inspection_start
```

- `units.inspection_start`(검사유효기간 시작일)는 sync-inspection-cache 크론이 매일 공단 API로 갱신한다 → §2의 "새 검사" 판단에 그대로 쓴다.
- 자동 해제를 안 하므로 크론은 건드릴 필요가 없다.

## 5. 개정법 탭 화면

- 열: 현장·호기, 담당자, 현재 판정, 검사유효기간 만료일, 단계 라벨, 구분 드롭다운
- 단계 라벨은 판정값에서 자동 — 차기안전검사 → "연장 중 (차기안전검사)", 조건부합격 → "연장 중 (조건부)", 합격 → "연장 종료 가능"
- 정렬: 만료일 빠른 순
