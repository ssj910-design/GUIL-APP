# 부품현황 사진 앨범형식 Design

## 목표

부품현황 리프(세부항목) 상세의 사진 표시를 지금의 캐러셀(1장씩 + 좌우 화살표)에서
그리드(앨범) 형식으로 바꾼다 — 여러 장을 한 번에 훑어보고, 클릭하면 전체화면으로
넘어간다. 삭제는 그리드에서 바로 하지 않고 전체화면에서만 한다(옵션 A, 브라우저
mockup으로 사용자 확인 완료) — 그리드에서 실수로 삭제 못 하게, 다운로드 아이콘
옆에 삭제 아이콘을 나란히 둔다.

모바일 앱(`PartPhotosPanel`의 `PartLeafRow`)과 관리자웹(`PartsStatusTab`의
`LeafDetail`) 둘 다 적용 대상 — 두 화면 다 같은 `FileCarousel`
(`app/components/admin/adminShared.jsx`)을 쓰고 있어서, 이 컴포넌트 하나에 손을
대면 양쪽에 다 반영된다.

## 범위

`FileCarousel`은 계약서·사업자등록증·인사관리 첨부파일 등 부품현황 밖에서도 널리
쓰인다 — 그 화면들은 지금처럼 캐러셀 방식(문서 1개씩 넘겨보기, PDF 섞임)을 그대로
유지해야 한다. 그래서 그리드는 새 옵트인 모드로 추가하고, 기존 호출부는 전부
기본값(캐러셀)으로 아무 변경 없이 유지한다.

## `FileCarousel` — `layout` prop 추가

```
layout = "carousel" | "grid"   (기본값 "carousel" — 기존 동작 100% 유지)
```

`layout="grid"`는 부품현황의 두 호출부(`PartLeafRow`, `PartsStatusTab`의
`LeafDetail`)에서만 쓴다. 다른 모든 `FileCarousel` 호출부는 `layout`을 안 넘기므로
기본값으로 지금 그대로 동작한다.

**grid 모드일 때:**
- 큰 사진 1장 + 좌우 화살표 + 우측상단 "N/전체" 배지를 안 그린다.
- 대신 정사각형 썸네일 그리드(`object-fit: cover`)를 그린다. 열 수는 고정 숫자가
  아니라 CSS `grid-template-columns: repeat(auto-fill, minmax(76px, 1fr))`로 —
  컨테이너 폭에 따라 자동으로 줄어들거나 늘어난다. 그래서 관리자웹(넓은 상세
  영역)에서는 한 줄에 여러 칸, 모바일 아코디언(좁은 폭)에서는 한 줄에 3칸 정도로
  자연히 달라지고, 두 화면에 서로 다른 열 수를 따로 지정할 필요가 없다.
- 마지막 칸은 항상 점선 테두리의 "추가" 칸(+ 아이콘) — 클릭하면 기존
  `openPicker()`(사진 0장일 때 쓰던 것과 동일한 카메라/사진첩 선택 흐름) 그대로
  연결한다. 사진이 0장이면 추가 칸 하나만 있는 그리드가 된다(빈 상태 전용 UI 안 만듦).
- 사진 썸네일을 클릭하면 그 인덱스로 `PhotoLightbox`를 연다 — 지금 캐러셀 모드의
  큰 사진 클릭과 동일한 `viewerIndex` state, 재사용.
- 그리드 바깥 "삭제" 버튼(지금 캐러셀 모드에서 현재 사진 삭제하던 버튼)을 그리지
  않는다 — 삭제는 전체화면 전용이므로 grid 모드에서는 아예 없앤다.
- 드래그앤드롭은 그리드 컨테이너 전체에 그대로 건다(지금 캐러셀 프레임에 걸려
  있던 것과 동일한 `dragProps`).
- `height` prop은 grid 모드에서는 안 쓴다(고정 높이로 자르지 않고 사진 수만큼
  세로로 늘어나야 하므로) — 두 호출부(`PartLeafRow`의 `height="h-40"`,
  `PartsStatusTab`의 `height="h-64"`)는 `layout="grid"`로 바꾸면서 `height` prop
  자체를 지운다(안 넘겨도 grid 모드는 그 값을 참조하지 않으니 넘겨도 무해하지만,
  안 쓰는 prop을 남겨두지 않도록 같이 정리).

## `PhotoLightbox` — 삭제 추가

새 선택적 prop `onDelete`. 값이 있을 때만 헤더의 다운로드 아이콘 옆에 휴지통
아이콘을 그린다(없으면 지금처럼 다운로드+닫기만, 캐러셀 모드에서 쓰이는
기존 동작은 완전히 그대로).

- 휴지통 클릭 → 기존 `removeCurrent`와 동일하게 `confirmAsync("이 파일을
  삭제할까요?")`로 한 번 확인.
- 확인하면 `onDelete()` 호출(부모가 실제 삭제 처리 — `savePartLeafPhotos` 경유).
- 삭제 후: 남은 사진이 있으면 같은 자리(인덱스 clamp)에서 계속 보여주고, 마지막
  한 장이었으면 라이트박스를 자동으로 닫는다.

`layout="grid"`인 `FileCarousel`만 `onDelete`를 넘긴다 — 캐러셀 모드 호출부(계약서
등)는 `onDelete`를 안 넘기므로 휴지통이 안 보이고 동작도 지금과 완전히 동일하다.

## 데이터 흐름

기존 `savePartLeafPhotos`/`onAdd`/`onRemove`는 그대로 재사용 — 이번 변경은 순수
표시 방식(캐러셀→그리드)과 삭제 트리거 위치(버튼→라이트박스) 변경이지, 사진
추가/삭제 판별 로직(`lib/partLeafPhotos.js`)에는 영향 없다.

## 범위 밖

- 다른 화면(계약서·사업자등록증·인사관리 첨부)의 `FileCarousel` 표시 방식 변경 —
  그대로 캐러셀 유지.
- 그리드에서 여러 장을 한 번에 선택해 삭제하는 기능(멀티셀렉트) — 요청 범위 아님.
- 순서 변경(드래그로 재배열) — 요청 범위 아님.
