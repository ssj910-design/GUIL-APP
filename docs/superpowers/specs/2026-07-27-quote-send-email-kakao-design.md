# 견적서 발송 (이메일 + 카카오 알림톡) — 설계

## 배경

`2026-07-24-quote-pdf-admin-design.md`에서 "범위 밖"으로 미룬 두 채널(이메일, 카카오 알림톡)을
이번에 구현한다. 견적서 자체는 이미 관리자웹에서 품목편집 → PDF 생성까지 완료돼 있고(`quote_pdf_url`에
Supabase Storage 공개 URL로 저장됨), 이번 작업은 그 PDF를 실제 고객(현장 담당자)에게 전달하는
발송 단계만 추가한다.

## 발송 시점과 흐름

발행 확정과 발송은 **분리된 별도 동작**이다. "견적발행" 상태가 된 건을 관리자가 PDF로 먼저 확인한 뒤,
목록에서 별도 **"발송"** 버튼을 눌러야 실제로 나간다(발행 즉시 자동 발송 아님 — 관리자가 확인할
여지를 준다).

발송 모달을 열면:
1. 현장의 주담당자(`site_managers`에서 `is_primary = true`인 사람)의 이메일/전화번호를 기본값으로
   채운다. 담당자가 없거나 정보가 비어 있으면 빈 칸으로 시작.
2. 관리자가 그 자리에서 이메일/전화번호를 직접 수정할 수 있다.
3. 이메일/카카오 알림톡 체크박스(기본 둘 다 켜짐) — 필요 없는 채널은 꺼서 하나만 보낼 수도 있다.
4. "발송" 클릭 시 두 채널을 **독립적으로** 시도한다 — 하나가 실패해도 다른 하나는 그대로 진행되고,
   결과를 채널별로 따로 보여준다(✅/❌ + 실패 사유). 조용히 실패를 숨기지 않는다는 기존 원칙과 동일.
5. 성공한 채널은 실제 사용된 수신처와 발송 시각을 저장한다. 재발송(같은 견적을 다시 열어 또 보내기)도
   그대로 지원 — 발송 이력을 별도로 쌓지는 않고 "마지막 발송" 정보만 덮어쓴다(버전 이력 없음, 기존
   견적 재발행과 같은 정책).

## 채널별 구현

### 이메일 — 네이버 SMTP

Resend(도메인 인증 필요)와 네이버 SMTP를 비교한 결과, **회사가 별도 도메인을 구입할 계획이 없어서
네이버 SMTP로 결정**했다. 도메인 인증 없이도 바로 실제 고객에게 발송 가능하다는 게 결정적 이유.

- `lib/email.js` — `sendQuoteEmail({ to, quote, pdfUrl })`: `nodemailer`로 `smtp.naver.com`(포트 465,
  SSL)에 접속해 발송. 발신자: `guil2020@naver.com`.
- 인증은 네이버 앱 비밀번호 사용(일반 로그인 비밀번호 아님 — 2025-06-24부터 네이버가 SMTP 접속에
  2단계 인증+앱 비밀번호를 의무화함). 환경변수: `NAVER_SMTP_USER`, `NAVER_SMTP_APP_PASSWORD`.
- 본문: 카카오 알림톡과 같은 문구(아래 템플릿 참고)를 이메일 형식으로 재구성. 제목은
  `[구일엘리베이터] 견적서 안내 - {현장명}`.
- **PDF는 링크가 아니라 실제 첨부파일로 붙인다** — 서버에서 `quote.quotePdfUrl`을 fetch해 바이트를
  받아 첨부(이메일은 카카오와 달리 첨부가 자연스러운 채널이라 다운로드 없이 바로 열람 가능하게).
- 알려진 리스크: 개인 네이버메일의 정확한 일일 자동발송 제한이나 스팸 판정 기준은 네이버가 공개하지
  않는다. 이 앱은 관리자가 건별로 수동 발송하는 방식이라 하루 수십 통 이내로 예상되고, 그 정도
  볼륨에서는 실무상 문제가 될 가능성이 낮다고 보고 진행한다. 나중에 실제로 발송이 막히거나 도메인을
  구입하게 되면 `lib/email.js` 내부만 Resend로 교체하면 되도록 발송 로직을 이 파일에 격리해 둔다.

### 카카오 알림톡 — 알리고

중계사는 알리고(Aligo) — 채널 개설·중계사 가입 완료됨. 템플릿은 아래 문구로 등록 신청까지 마침
(카카오 검수 영업일 기준 3~5일 소요).

**등록 신청한 템플릿 문구:**

```
【승강기 부품 교체 견적 안내】

안녕하세요, #{현장명} 담당자님.
안전하고 원활한 승강기 운행을 위해 아래 부품 교체 관련 견적서를 발송해 드립니다.

■ 견적명: #{견적명}
■ 견적일: #{견적일}

아래 버튼을 눌러 견적서 확인 후 승인(회신)해 주시면, 부품 수급 및 일정을 조율하여
신속하고 안전하게 교체 공사를 진행하도록 하겠습니다.

늘 안전을 최우선으로 꼼꼼하게 관리하겠습니다. 감사합니다.

견적 담당: 신석주 차장(010-2939-2431)
```

버튼: "견적서 확인하기" (웹링크). 모바일/PC 링크 둘 다 `https://kdptzotxnzpuwzdguzgh.supabase.co/#{링크}`로
등록(카카오는 링크의 도메인이 고정돼 있어야 심사를 통과시킴 — 도메인 뒤 경로만 변수로 뺐다).

- `lib/alimtalk.js` — `sendQuoteAlimtalk({ to, quote, pdfUrl })`: 알리고 알림톡 발송 API 호출.
  - 변수: `현장명`, `견적명`, `견적일`, `링크`(= `pdfUrl`에서 `https://` 프로토콜과 도메인을 뺀 나머지
    경로 전체 — 등록한 템플릿의 고정 도메인과 짝이 맞아야 함).
  - 실패 시(카카오톡 미가입, 수신차단 등) **SMS 자동 대체발송 켬** — 알리고가 지원하는 옵션, 건당 SMS
    비용이 별도로 발생하는 것을 감수하고 진행(사용자 확인 완료).
  - 환경변수: `ALIGO_API_KEY`, `ALIGO_USER_ID`, `ALIGO_SENDER_KEY`(카카오 발신프로필키),
    `ALIGO_SENDER_PHONE`(SMS 대체발송용 사전등록 발신번호), `ALIGO_TEMPLATE_CODE`(카카오 승인 후
    발급되는 코드 — 승인 전까지는 이 값이 없어 실제 발송 테스트는 승인 후에나 가능).

## API 라우트

`POST /api/send-quote`:

- 요청 바디: `{ quoteRequestId, channels: { email: boolean, kakao: boolean }, recipientEmail, recipientPhone, quote: {...PDF 생성에 쓰인 것과 같은 필드 + pdfUrl} }`
- 채널마다 독립적으로 try/catch — 하나의 실패가 다른 채널 처리를 막지 않는다.
- 응답: `{ results: { email: {ok, reason?}, kakao: {ok, reason?} } }` (요청한 채널만 포함)
- 성공한 채널에 한해 `quote_requests`를 업데이트: `recipient_email`, `recipient_phone`(실제 사용된 값),
  `email_sent_at`과 `kakao_sent_at` 중 성공한 쪽의 타임스탬프.

## 데이터 모델

`quote_requests`에 컬럼 추가:

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `recipient_email` | text | 발송한(또는 마지막으로 입력한) 수신 이메일 |
| `recipient_phone` | text | 발송한(또는 마지막으로 입력한) 수신 전화번호. 기존 `contact_phone`(기사가 접수 시 입력한 연락처)과는 다른 값 — 이건 발송 대상(현장 담당자) 전용. |
| `email_sent_at` | timestamptz | 이메일 발송 성공 시각(null이면 미발송) |
| `kakao_sent_at` | timestamptz | 카카오 알림톡(또는 SMS 대체) 발송 성공 시각(null이면 미발송) |

## 관리자 UI

`app/components/admin/QuoteSendModal.jsx`(신설) — "견적발행" 상태 행에 기존 승인처리/품목수정/PDF보기
버튼 옆에 **"발송"** 버튼을 추가해서 연다. 이미 한 번 발송한 건도 다시 열어 재발송 가능(정보 그대로
불러와서 보여줌 — `recipient_email`/`recipient_phone`이 있으면 그 값을, 없으면 site_managers 주담당자
값을 기본값으로).

## 에러 처리 원칙

- 이메일/카카오 각각 성공·실패를 명확히 구분해서 보여준다. 부분 성공(하나만 성공)도 정상 상태로
  받아들이고, 실패한 채널만 다시 시도할 수 있게 한다.
- 알리고 템플릿이 아직 카카오 승인 전이면 카카오 발송은 항상 실패로 응답한다(승인 전 코드가 없어서
  API 자체가 에러를 반환함) — 이 경우도 조용히 숨기지 않고 실패 사유를 그대로 보여준다.

## 구현 전 준비 사항 (사람이 직접 해야 하는 것)

1. 네이버메일 2단계 인증 켜고 앱 비밀번호 발급 → Vercel 환경변수 `NAVER_SMTP_USER`,
   `NAVER_SMTP_APP_PASSWORD` 등록.
2. 알리고 템플릿 카카오 승인 대기 중(등록 신청 완료, 영업일 3~5일) — 승인되면 발급되는 템플릿 코드를
   `ALIGO_TEMPLATE_CODE`로 등록.
3. 알리고 API 키/사용자 아이디/발신프로필키/발신번호 → 각각 환경변수로 등록.
4. 마이그레이션(`supabase/migrations/065_quote_send_DRAFT.sql`, 위 4개 컬럼 추가) 실행.

카카오 템플릿 승인 전까지는 이메일 채널만 실제로 테스트 가능하다 — 카카오 쪽 코드는 미리 구현해두고,
승인 나면 템플릿 코드만 환경변수에 넣어 바로 쓸 수 있게 한다.

## 범위 밖

- 견적 발송 이력(누가 언제 몇 번 보냈는지) 전체 로그 — "마지막 발송" 정보만 저장, 과거 이력은 안 남김
- 발행 즉시 자동 발송(관리자 확인 없이) — 명시적으로 제외, 항상 수동 "발송" 버튼
- 이메일 열람 확인, 카카오 알림톡 읽음 확인(수신 확인) — 알리고 웹훅 연동 등은 다음 단계
- 여러 수신자에게 동시 발송(참조/숨은참조, 여러 담당자 동시 전송) — 1건당 1명만
