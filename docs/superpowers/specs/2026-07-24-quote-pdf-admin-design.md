# 견적요청 품목화 + 견적서 PDF 생성 (관리자웹) — 설계

## 배경

기사가 견적요청을 신청할 때는 지금처럼 부품명·수량만 간단히 입력한다(변경 없음). 관리자가
그 요청을 검토해 실제 견적서에 들어갈 세부 품목(자재비/인건비 구분·규격·단위·단가 등)으로
확장하고, 확정하면 회사 지정 양식(견적서)에 맞춰 PDF를 생성한다.

이메일/카카오 알림톡으로 실제 발송하는 것은 다음 단계 범위다 — 이번엔 **품목편집 + PDF 생성**까지만
관리자웹(`/admin`)에 구현한다.

## 원본 양식 자료

- 회사 견적서 양식(엑셀): `D:\견적\견적양식(인건비 세부).xls` — 시트 "견적서"에 셀 좌표·수식(금액=수량×단가,
  소계=SUM, 합계=INT(소계/1000)*1000)까지 확인됨. 최종 구현에서 이 파일을 직접 조작하진 않고,
  레이아웃·계산 로직의 "정답"으로만 참고한다.
- 같은 양식의 PDF 버전: `C:\Users\crewj\Downloads\견적양식(인건비 세부).pdf` — 입력 필드 없는 고정
  이미지형 PDF. 레이아웃 참고용으로만 쓰고, 배경으로 얹어 쓰지는 않는다(아래 "왜 배경 오버레이가
  아닌가" 참고).
- 회사 로고: `D:\구일\스티커디자인\구일엘리베이터(주)-로고 (1).ai` — PDF 호환 저장이라 그대로 열람
  가능. 구현 시 PNG로 한 번 변환해 `public/`(또는 유사 위치)에 자산으로 넣고 pdf-lib에서 재사용한다.

### 왜 "기존 PDF를 배경으로 텍스트만 얹는 방식"이 아닌가

처음엔 기존 PDF 파일을 배경 이미지로 쓰고 빈칸에만 텍스트를 그리는 방식을 검토했다. 그런데 실제
운영에서는 **자재비 5줄·인건비 6줄이라는 양식의 고정 칸 수를 넘는 경우가 자주 있다**는 게 확인돼
이 방식은 못 쓴다(칸이 넘치면 아래 소계·합계 표와 겹침). 그래서 레이아웃을 코드에서 직접 그리는
방식으로 바꿨다 — 품목 줄 수에 제한이 없고, 한 페이지에 안 들어가면 자동으로 다음 페이지로 넘어간다.

## 데이터 모델

`quote_requests` 테이블에 컬럼 추가 (마이그레이션은 별도 DRAFT SQL, 아래 참고):

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `quote_items` | jsonb | 품목 배열. 각 항목: `{category: "자재비"\|"인건비", name, unitNo, spec, unit, qty, unitPrice}`. 금액(qty×unitPrice)은 저장하지 않고 표시·PDF 생성 시마다 계산한다 — 저장값과 실제 계산이 어긋나는 걸 방지. |
| `transport_cost` | numeric | 운반비 (직접 입력, 양식의 "3.운반비" 행) |
| `safety_cost` | numeric | 안전관리비 및 기타 (직접 입력, 양식의 "4." 행) |
| `profit` | numeric | 이윤 (직접 입력, 양식의 "5." 행) |
| `quote_number` | text | 견적서 No. |
| `recipient_name` | text | 수신자 (예: "OO빌딩 관리소장 귀중") |
| `quote_title` | text | 견적명 |
| `quote_pdf_url` | text | 생성된 PDF의 Supabase Storage URL |

품목 줄 수는 제한 없음(양식 원본의 5+6줄 제약은 코드로 그리는 방식이라 적용 안 됨).

기존 필드는 그대로 유지:
- `part`(기사가 신청한 부품명), `quantity`(기사가 신청한 수량) — 관리자 편집 화면에 "기사 요청 원본"으로
  읽기전용 참고 표시. 편집 시작할 때 자재비 첫 줄에 프리필해서 관리자가 다시 타이핑 안 해도 되게 한다.
- `constructionType`, `contactPhone`, `note`, `photoUrls` 등 나머지 — 변경 없음.

## 관리자 UI 흐름

`app/components/admin/MaterialsAdmin.jsx`:

- 현재: "견적발행 처리" 버튼 클릭 → `handleQuoteAdvance`가 즉시 `status: "견적발행"`, `quote_issued_date`만
  갱신(입력 없는 전환).
- 변경 후: 상태가 "요청접수"일 때 그 버튼을 누르면 **품목편집 모달**(`QuoteItemsModal` 신설)이 열린다.
  모달 안에서 "발행 확정"을 눌러야 실제로 상태가 바뀐다 — 빈 견적으로는 발행 불가(품목 0개면 확정
  버튼 비활성화).
- 이미 "견적발행" 상태인 건을 다시 열면(재편집), 저장된 값을 불러와 수정 후 재발행할 수 있다(PDF 재생성,
  버전 이력은 없음 — 최신 값으로 덮어씀).

### 모달 구성

1. **기사 요청 원본** — 부품명·수량·현장·호기·사진(있으면), 읽기전용 카드.
2. **상단 정보 입력** — 수신자, 견적명, 견적일(기본 오늘), 견적서 No.(수기 입력 또는 빈 값 허용).
3. **품목 테이블** — 자재비/인건비 섹션 구분, 각 섹션 안에서 행 추가/삭제/수정(품명·호기·규격·단위·수량·단가).
   행 옆에 금액(수량×단가, 자동계산·읽기전용) 표시.
4. **운반비/안전관리비/이윤** — 숫자 입력 3칸.
5. **합계 미리보기** — 소계(자재비+인건비+운반비+안전관리비+이윤 합), 합계(소계를 1000단위 절사) 실시간 표시.
6. **발행 확정 버튼** — 클릭 시:
   - `quote_items` 등 위 필드를 `quote_requests`에 저장
   - 서버에 PDF 생성 요청 → 생성된 PDF를 Storage에 올리고 `quote_pdf_url` 저장
   - `status: "견적발행"`, `quote_issued_date` 갱신
   - 실패 시(PDF 생성 실패 등) 상태 전환은 하지 않고 에러를 명확히 보여준다(조용히 숨기지 않음 — T맵 키
     누락 때 배운 교훈).

발행 후에는 목록에서 "PDF 보기" 링크로 `quote_pdf_url`을 열람할 수 있다.

## PDF 생성

새 서버 API 라우트 `app/api/generate-quote-pdf/route.js` (POST):

- 요청 바디: 위 필드 전부(quote_items, transport_cost 등) + 현장 정보(siteName, address 등 필요한 값).
- pdf-lib로 **레이아웃을 코드에서 직접 그린다** (기존 PDF/엑셀 파일은 열지 않음 — 순수 참고자료):
  - 상단: 로고(embedPng) + "견 적 서" 타이틀 + 공급자 고정정보(회사명·등록번호·주소·연락처— 코드에
    하드코딩, 매번 동일) + 수신자·견적명·견적일·유효기간(견적일로부터 1개월, 고정 문구)
  - "일금 OOO원정" — 합계 금액을 한글로 변환하는 함수 필요(신규 유틸, 예: `lib/koreanNumber.js`)
  - 품목 테이블: 헤더 행(품명/호기/규격/단위/수량/단가/금액) 그리고, "1.자재비"/"2.인건비" 구분 라벨 +
    각 품목 행을 순서대로 그림. 한 페이지에 다 안 들어가면 새 페이지 추가, 표 헤더도 반복.
  - "3.운반비"/"4.안전관리비 및 기타"/"5.이윤" 행 + 소계·합계 행(계산은 서버 JS에서: 항목별
    금액=수량×단가 합 + 나머지 3개 → 소계, `Math.floor(소계/1000)*1000` → 합계)
  - 특이사항 3개 문구(교체부품 보증기간·폐부품 회수 동의·시간외 작업 할증) — 고정 텍스트, 항상 마지막에.
- 생성된 PDF를 `lib/photos.js`의 업로드 패턴과 동일하게 Supabase Storage(`photos` 버킷, 예:
  `quotes/{quoteRequestId}` 폴더)에 올리고 공개 URL을 응답으로 반환.
- 실패 시 `{ ok: false, reason }` 형태로 응답(T맵 라우트와 동일 패턴) — 클라이언트는 이걸 그대로
  사용자에게 노출한다.

## 에러 처리 원칙

- PDF 생성 실패, Storage 업로드 실패 등 어떤 단계든 실패하면 **관리자 화면에 실패 사유를 명확히 표시**하고
  상태는 바뀌지 않은 채로 둔다(부분 실패로 상태만 앞서가는 걸 방지).
- 로고 이미지 자산이 아직 준비되지 않은 경우를 대비해, 로고 로드 실패 시에도 PDF 생성 자체는 계속되게
  하되("GUIL ELEVATOR" 텍스트로 대체) 전체 기능이 막히지 않게 한다.

## 마이그레이션

`supabase/migrations/060_quote_items_DRAFT.sql`(가칭) — 위 표의 컬럼들을 `quote_requests`에 추가하는
`alter table ... add column if not exists` 구문. 기존 데이터에 영향 없음(전부 nullable). 실행 전 사용자
확인 절차는 기존 관례대로.
