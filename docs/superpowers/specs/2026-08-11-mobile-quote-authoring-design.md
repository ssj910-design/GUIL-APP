# 관리자 모드 폰앱 — 견적관리·새견적작성 — 설계

## 배경

지금 관리자가 폰(네이티브 앱, `ElevatorFieldApp.jsx`의 관리자 모드 `AdminTab.jsx`)으로 로그인하면
"견적요청관리" 아코디언에서 기사가 올린 견적요청을 볼 수 있지만, **"견적발행 처리" 버튼을 눌러도
실제 품목·금액이 담긴 견적서(PDF)는 전혀 만들어지지 않는다** — `quote_requests.status`를
"요청접수"→"견적발행"으로 바꾸고 `quote_issued_date`만 채우는 라벨 갈이일 뿐이다
(`ElevatorFieldApp.jsx` 견적 진행 단계 전진 로직, `AdminTab.jsx:258`의 `onAdvanceQuote` 호출부 확인).
실제 품목·운반비·안전관리비·이윤을 입력하고 PDF를 만드는 화면은 PC용 관리자웹
(`MaterialsAdmin.jsx` + `QuoteItemsModal.jsx`, `/api/generate-quote-pdf` 호출)에만 있고, 네이티브
앱은 오히려 이 화면으로 못 가게 막혀 있다(`ElevatorFieldApp.jsx`가 PC 브라우저에서 접속한
관리자만 웹 콘솔로 리다이렉트, 네이티브 앱은 그대로 자체 화면에 남음).

원래 이 문제를 텔레그램 봇(문장 파싱)으로 풀려고 했으나(`2026-08-04-telegram-quote-bot-design.md`),
다품목·운반비·안전관리비·이윤까지 다 받으려니 자연어 파싱으로는 정확도가 불안했고, 이미 검증된
PC 관리자웹 폼 로직을 그대로 재사용할 수 있다는 점에서 **폰 앱 안에 진짜 입력 화면을 만드는 쪽으로
방향을 바꿨다.** 텔레그램 봇 작업(Task 1~4: 마이그레이션 컬럼, `lib/telegram.js`,
`lib/telegramQuoteParse.js`, `@anthropic-ai/sdk`)은 삭제하지 않고 보류만 한다.

## 목표

관리자가 폰 앱에서: (1) 기사가 올린 기존 견적요청을 보고 그 자리에서 바로 진짜 견적서(품목·금액·PDF)를
작성하거나, (2) 요청과 무관하게 처음부터 새 견적서를 작성할 수 있게 한다. PC 관리자웹의 로직
(품목 추가/삭제/순서변경, 금액 계산, PDF 생성 API, 빈 초안 정리)은 최대한 그대로 재사용하고
화면(JSX)만 폰에 맞게 새로 만든다.

## 메뉴 구조 변경

- `AdminTab.jsx`의 아코디언 항목 "견적요청관리" → **"견적관리"**로 이름 변경.
- 지금은 아코디언(눌러서 그 자리에서 펼쳐짐, `expanded` state)인데, **전체화면 진입 방식**(`page`
  state — 지금 청구관리/자재이력/견적이력이 쓰는 방식과 동일)으로 바꾼다.

## 견적관리 화면

기존 `QuotesPanel`의 목록(진행중 요청 카드, 상태별 배지, `SwipeCarousel`)은 그대로 두고 두 가지를 더한다:

1. **목록 상단에 [+ 새 견적 작성] 버튼** — 기사 요청과 무관하게 완전히 새 견적을 시작. 누르면
   아래 "새 견적 작성 마법사"가 1단계(현장 선택)부터 열린다.
2. **"요청접수" 상태 카드의 동작 변경** — 지금은 [견적발행 처리] 버튼이 상태 라벨만 바꾸는데,
   앞으로는 **마법사를 2단계(품목 입력)부터 열어서** 진짜 견적을 작성하게 한다. 이때 품목 1번의
   품명은 기사가 남긴 요청 텍스트(`constructionType`/기존 매핑 필드, 상세시트의 "견적 내역")를
   참고해 미리 채워주고, 수신처는 요청에 담긴 현장 담당자 연락처(`contactPhone`)가 있으면 기본값으로
   쓴다 — 둘 다 마법사 안에서 관리자가 그대로 확인·수정 가능.
   - "견적발행" 이후 상태(승인 등)의 카드는 지금 동작(상세보기·자재지급 사진 등) 그대로 둔다 —
     이미 PDF가 있는 건이라 마법사를 다시 열 필요가 없다.

## 새 견적 작성 마법사

고장접수 폼(`FailureTab.jsx`)과 같은 스텝형 UI(상단 4칸 진행바 + 단계 제목 + 하단 이전/다음)를
그대로 따른다.

1. **현장·담당자 선택** — 현장 검색(기존 `QuoteNewSiteModal`과 동일한 리스트, 새 화면은 검색
   UI만 재사용) + 수신 담당자(기존 `useQuoteRecipientFields` 훅의 로직 재사용, UI만 폰에 맞게).
   기존 요청에서 들어온 경우 이 단계 전체를 건너뛴다.
2. **품목 입력** — **아코디언 카드** 방식. 품목이 여러 개면 카드로 쌓이고, 편집 중인 카드만
   펼쳐져 필드(카테고리/품명/규격/수량/단위/단가)가 보이고 나머지는 "품명 · 수량단위 × 단가 =
   소계" 한 줄로 접힌다. `[+ 품목 추가]`로 새 카드. 품목 추가/삭제/순서 계산 로직은
   `QuoteItemsModal.jsx`의 기존 상태 로직을 그대로 재사용하고 렌더링만 새로 만든다.
3. **운반비·안전관리비·이윤** — 데스크탑과 동일한 세 필드(+ 할인이 있으면 그것도), 하단에
   실시간 합계 표시.
4. **확인·발행** — 현장·담당자·전체 품목·부대비용·합계 요약을 한 화면에 보여주고 **[발행하기]**.

## 데이터 흐름 (기존 로직 재사용)

- **빈 초안 생성**: `[+ 새 견적 작성]`으로 시작해 1단계에서 현장을 고르고 "다음"을 누르는 순간,
  데스크탑 `handleCreateQuote`(`MaterialsAdmin.jsx:503-526`)와 동일한 shape로 `quote_requests`에
  빈 행을 insert한다(`construction_type: "관리자 발행"`, `requester_id`/`engineer` 둘 다 null —
  기존 방식과 일관되게 `created_by`는 추가하지 않는다). 기존 요청에서 들어온 경우는 이 단계가
  없다 — 그 요청 행을 그대로 쓴다.
- **2~3단계는 로컬 상태로만 편집** — 매 필드 입력마다 저장하지 않는다.
- **4단계 [발행하기]** — 기존 `/api/generate-quote-pdf` API 라우트를 그대로 호출(품목·부대비용·
  수신처 전달) → 그 라우트가 PDF 생성·Storage 업로드까지 처리 → 성공하면
  `quote_requests.status`를 "견적발행"으로, `quote_pdf_url`을 응답값으로 업데이트. **새 API를
  만들지 않는다.**
- **중도 이탈(뒤로가기로 마법사 닫기)** — 기존 빈 초안 정리 조건(`MaterialsAdmin.jsx:761-786`과
  동일: `status === "요청접수"` AND `requester_id`/`engineer` 둘 다 null일 때만 삭제)을 그대로
  적용. 기존 요청에서 들어온 경우는 애초에 이 조건을 만족하지 않으니(요청자 정보가 있음) 삭제되지
  않고 원래 상태(요청접수)로 남는다 — 나중에 다시 열어서 이어갈 수 있음.

## 범위 밖

- PC 관리자웹(`MaterialsAdmin.jsx`, `QuoteItemsModal.jsx`)은 건드리지 않는다 — 그대로 둔다.
- 텔레그램 견적봇은 삭제하지 않고 보류 — 이 기능과 무관하게 남겨둔다.
- 마법사 중간에 "이전 단계로 돌아가기"는 지원하되, 품목 카드 자체의 되돌리기(undo)는 없음 —
  삭제하면 그대로 삭제, 데스크탑도 동일.
- 자재담당관리자(`admin_tier === "material"`)는 지금처럼 이 메뉴 전체가 안 보임(기존
  `notifNewQuotes` 조건과 동일한 원칙 유지) — 새 마법사도 최고·중간관리자만 접근.

## 에러 처리

`/api/generate-quote-pdf` 실패 시 초안은 삭제하지 않고 4단계에 남겨서 재시도 가능하게 하고,
실패 사유를 화면에 그대로 보여준다(기존 관리자웹 에러 처리 원칙과 동일 — 조용히 실패를 숨기지
않는다). 빈 초안 insert 자체가 실패하면 1단계에서 진행을 막고 에러를 보여준다.
